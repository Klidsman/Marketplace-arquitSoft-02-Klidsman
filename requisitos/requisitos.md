| ID   | Restricción | Descripción |
|------|---------------|----------------|
| RC01 | Aplicación web | El sistema debe desarrollarse como una aplicación accesible mediante un navegador web. |
| RC02 | Control de versiones | El código fuente debe gestionarse utilizando Git y mantenerse en un repositorio compartido. |
| RC03 | API REST | La comunicación entre el frontend y los servicios del sistema debe realizarse mediante una API REST. |
| RC04 | Pasarela de pago | El sistema debe integrarse con una pasarela de pago externa para procesar las operaciones de pago. |
| RC05 | Servicio de envío | El sistema debe integrarse con un servicio externo de envío para gestionar la información relacionada con la entrega de pedidos. |
| RC06 | Servicio de facturación | El sistema debe integrarse con un servicio externo de facturación para la generación de comprobantes de pago. |
| RC07 | ERP externo | El sistema debe integrarse con un ERP externo para obtener información de productos y stock. |
| RC08 | Arquitectura basada en servicios | El sistema debe estructurarse mediante servicios independientes que se comuniquen entre sí, facilitando su escalabilidad y mantenimiento. |
| RC09 | Base de datos | El sistema debe utilizar un motor de base de datos compatible con las operaciones transaccionales del marketplace (pedidos, pagos, stock). |
| RC10 | Despliegue en la nube | El sistema debe poder desplegarse en una infraestructura en la nube que permita escalar recursos según la demanda. |
| RC11 | Compatibilidad multiplataforma | La aplicación web debe funcionar correctamente en los principales navegadores y ser responsive para distintos dispositivos. |
| RC12 | Normativas de protección de datos | El sistema debe cumplir con la normativa vigente de protección de datos personales aplicable a los usuarios del marketplace. |
